# GIT-HUB-TUTORIAL-BASICS
This is a fundamental concept clearing guide to how to work with GitHub.

Did you understand how I created this page on GitHub? 
If not, then let's dive in - 
1. Sign in to your github account and click on the + sign on the top panel of your screen. The + sign acts as a create button that provides users with many facilities that we will go one by one. For now we are focussing on how to create a repository on github.
2. Select "Create Repository"
3. Write the name of the repository, for an example I have named this tutorial as "GIT-HUB-TUTORIAL-BASICS"
4. After this you can also add a brief description about your repository. For "GIT-HUB-TUTORIAL-BASICS" repository I have added the description as - "This is a fundamental concept clearing guide to how to work with GitHub."
5. Next we turn on the README button, make it either private/public and save/create the repository. I have made this repository "public" because I want the coders community to grow!! :)
6. Your repository will be displayed on your account page

So let's dive deeper into the tech understanding on what a repository is and why do we need to create one?
A repository is like a "storage room". Here we keep all the codes, files, documentation and the change history. It is also known as repo and can be owned by individual person as an owner or a multiple group of people by adding them under "collaborators". You can make this repository public (open source) or private based on your needs. The collaborators whom you add can have the access to make updates to your repository. Next is a very important part about repository is "Version control". A version control helps to track the changes that you have made by keeping a well-documented history with the changes implemented. So that if something breaks midway, we can trace back using the version numbers to understand the lineage and address the bug. For an example, Version 1 is the initial commit changes to the repository, Version 2 is the next commit changes to the repository, Version 3 is the new commit change to the repository and so on... 
Ok now enough about repositories. We will keep growing our knowledge and understanding about repositories as we progress. For now lets dive into what a README file is? 

So, this repository that I am working on currently is generated using a README = ON. 
A README file is like a notebook containing information/details about the project that you have built/working and how can it be useful to the public community. So whatever that I have documented so far, I am writing on the README file so that my readers will be able to understand and clear their concepts on how to create your first repository on GitHub.
